# 航发职业技能等级认定平台 · Demo

依据本工程技术协议、需求清单和人员职责模型实现的可交互前端。参考 `bjy1984/qbms` 的命题题库流程、`bjy1984/examsystem` 的考试考务流程，独立实现统一数据模型与界面；未直接集成或运行两套后端。

## 启动

需要 Node.js 20.19+（本机验证 Node 24.19）及 pnpm。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

打开 http://127.0.0.1:5173/ 。默认开发管理人员李志远，右上角可切换21位合成演示人员，无需真实登录。李志远可在页脚重置演示数据。“演示导航”集中提供七条协议业务主线，共44个可进入的操作环节。

```sh
pnpm build        # TypeScript 检查与生产构建，输出 dist/
pnpm preview     # 本地查看生产构建
pnpm test        # 业务规则测试
pnpm exec playwright install chromium
pnpm test:e2e    # 另一个终端保持 pnpm dev 运行
```

E2E 支持 `DEMO_URL` 和 `BROWSER_BIN` 指定服务地址及 Chromium 可执行文件。本机工具路径问题可使用 Codex 自带 Node/pnpm；项目无需 Xcode。构建产物须通过 HTTP 服务打开，不能直接双击 index.html。

## 建议演示顺序

1. 李志远创建命题计划，选择命题负责人、命题专家及各轮处理人后发布；已有计划可通过“任务分工”调整，待处理题目同步新的审核分配。
2. 张明从“我的任务”命制理论题并提交；李静初审，可退回给张明修改后再次提交。
3. 刘伟复审、周岚终审、周负责人执行入库，各自只看到所分配的当前任务。全过程记录实际操作人员。
4. 许库管管理题库，孙强固定选题或按规则组卷；赵考务配卷至考试场次。
5. 演示考生01核验、答题、模拟保存失败与刷新续考，交卷后查看个人报告。切换考生02无法读取或修改考生01答卷。
6. 吴阅卷分配评阅任务；陈工、赵敏分别提交评分，不在弹窗中代选其他评委。超差后由郑仲裁处理。
7. 赵考务配发技能评分任务，钱考评使用移动布局评分；不再要求协议未明确的现场评分签名，提交保留操作人员记录。
8. 林资料维护电子书，学习用户01仅阅读已发布资源；接口维护员处理模拟交换和失败重试。

也可以从“演示导航”进入七条业务主线，共44个环节，每步切换至对应演示人员。

## 数据和边界

- Vue 3 + TypeScript + Pinia + Vue Router + Vite，自定义响应式 CSS；Excel 使用 SheetJS，图标本地打包。
- 数据保存在当前浏览器 `localStorage`，当前人员保存在 `sessionStorage`。同源标签页同步；不同设备不共享。清理浏览器数据会丢失修改。数据备份为 JSON 导出，暂不提供备份导入恢复。
- 考生视图过滤答案字段，评分视图显示匿名号；完整种子仍在浏览器中。这是流程演示，不具备服务端鉴权、题目保密或生产防作弊能力。
- 三审、阅卷和仲裁由不同合成人员演示交接。角色和任务校验在前端执行，不替代生产环境服务端鉴权。考生及阅卷签字仍为姓名文本留痕，不是手写采集或数字签名。
- 随机组卷采用固定的题型和来源比重；手工选题自动均分100分。高级比重编辑、人工换题、跨科目优化暂未实现。
- 人脸、SSO、HR、人社及成绩交换是模拟；不申请摄像头或访问真实外部系统。名单和座位为合成数据，座位交换只在当前弹窗展示。
- Excel 仅支持本页面提供的窄模板；学习资料为自制文本及 `.txt` 上传，不含500本电子书或完整阅读器。
- 当前验证 Chromium 桌面、1280px投屏及390px技能评分；IE8、国产浏览器、真实平板、多设备协同、2000人并发、加密和灾备均未验收。

详细交付与验证见 [开发记录](docs/Demo开发与验证记录.md)、[滚动计划](docs/甲方演示Demo实施计划.md)、[65项范围映射](docs/Demo任务范围映射.md)。

## 目录树操作

题库资源、知识结构管理、命题编辑共用“工种 → 等级 → 科目 → 知识点”目录。点击节点筛选后代试题，箭头展开收起；支持目录搜索、路径返回、刷新保留选择。管理人员在知识结构中选中父级即可新增下级，也可更名、停用、删除空节点。命题页使用“从目录树选择”一次填入完整归属。

树结构浏览器验证：保持开发服务运行后执行 `node tests/trees.e2e.mjs`（同样支持 `BROWSER_BIN`）。


## 七条协议主线

打开 `/#/journeys` 或“演示导航”。每个环节提供协议条款、角色、操作说明及工作区入口；业务页面不显示演示引导，再次打开导航可继续上次主线。详细流程、新增交互及Mock边界见 [七条协议主线Demo说明](docs/七条协议主线Demo说明.md)。

新增测试：`pnpm test:journeys`；目录树回归：`pnpm test:trees`、`pnpm test:roles`。均须保持开发服务运行，支持环境变量 `BROWSER_BIN` 指定浏览器。

## 人员职责改版验证

- `pnpm test`：业务规则、协议主线及人员授权、跨人员交接、越权阻断测试。
- `pnpm test:roles`：21位演示人员的导航、三审入库、双评仲裁、停用授权和移动布局。
- `pnpm test:e2e`：命题、组卷配发、考生作答续考、评分回传、导入和阅读回归。
- `pnpm test:journeys`：七条主线44个环节及业务动作。
- `pnpm test:trees`：目录维护、筛选、命题选择和移动布局。

旧浏览器业务数据保留，并补充缺失的演示身份及任务分配；已有结构化授权不会在刷新时重置。旧自由文本角色不直接解释为新权限。新角色说明见 [人员职责改版记录](docs/Demo人员职责改版记录.md)。
