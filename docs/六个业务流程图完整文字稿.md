依据：项目文件《技术协议（招标文件）.docx》第一部分技术要求。核对日期：2026-09-21。

本稿以协议原文为范围依据，不以Demo页面、21位演示人员、既有功能清单中的建议或行业惯例替代合同要求。集团《题库开发管理办法》的具体条文未随本次协议文件提供，因此不补写该办法中的审批、回避或权限规则。

## 一、使用及绘图口径

### 1. 三种标记

- **【明确】**：协议直接规定的功能、规则、对象或参与者；文字为便于绘图的归纳，不一定是逐字引用。
- **【编排】**：为表达业务衔接设置的开始、结束、选择、汇合、连接点和异常出口；不是新增功能或协议已规定的唯一顺序。
- **【待确认】**：已有功能的执行人、时点、条件或处理路径没有明确。图中使用虚线及问题编号标注，不作为已确认开发规则。

主表中的功能节点均有协议依据；“建议泳道”属于职责归纳。除条款直接明确外，不能据此认定该岗位必须独立设置，或默认该职责拥有所列模块的全部权限。

### 2. 图形与节点文字

- 圆角框：开始／结束或跨图交接。
- 普通矩形：人工业务操作。
- 带“系统”标记的矩形：系统自动处理。
- 菱形：业务条件判断；其出线必须写明条件。
- 文档／数据形：试题、试卷、任务、评分表、成绩、报告、日志等输入输出。
- 虚线框：待确认的规则、角色或具体路径。
- 图底横向带：贯穿全流程的权限、安全、日志、统计与追溯，不能画成只在最后才执行的节点。

所有节点采用F1—F6前缀。主表“框内文字”可直接用于绘图；“说明及输入输出”放入图注或节点说明。主线、分支和循环在每图的连接清单中给出，不能只绘制表格顺序而忽略分支。

## 二、F1 题库开发与修订入库

### 1. 图名、目的、范围

图名：**题库开发与修订入库流程**。

图内说明：依据国家职业标准或企业评价规范，组织理论和技能试题开发，完成专家任务分配、在线命制、去重、协作、多轮审核、版本管理和入库；已入库试题因行业技术或政策变化可修订并重新审核。

适用范围：理论题库开发、技能题库开发；母题库、子题库、通用题库开发分类。10余种题型，不以Demo的6类题型作为范围上限。

### 2. 泳道文字

1. **题库开发组织方／管理端操作人员**：管理科目、计划、任务、专家、授权和进度。
2. **命题负责人**：项目负责及专家端相关业务；具体职责与管理端分工待确认。
3. **命题专家**：接收命题任务、命制和修订试题、响应协作意见。
4. **初审人员**：初审及意见处理。
5. **复审人员**：复审及意见处理。
6. **终审人员**：终审及意见处理。
7. **获授权的任务特批／入库操作人员**：角色归属待确认；特批和入库是不同权限，不因共列泳道就默认同一人执行。
8. **系统自动处理**：匹配、去重、意见汇总、流转、版本、日志和统计。
9. **外部／关联系统**：原考务系统、集团职业技能等级认定信息管理系统、F2题库管理。

初审、复审、终审泳道为业务职责划分，不表示协议规定必须由三个不同自然人担任。

### 4. 连线与分支文字

- F1-S → F1-01／F1-02 → F1-03：**准备命题基础与专家资源，制定计划**。基础资料已存在时可直接使用，不要求每次重新维护。
- F1-03 → F1-04 → F1-05：**匹配并分配任务**。F1-06以协作关系连接F1-03、F1-05和命审过程，不画成未经明确的强制审批关口。
- F1-05 → F1-07 → F1-08：**接收任务并命制**。
- F1-08 → F1-09：**技能试题**；F1-08直接进入后续命审：**理论试题**。F1-09完成后汇回命审主线。
- F1-10 → F1-11 → F1-08／F1-09：**汇总意见并完善试题**；命制及每轮审核均可连接该协作支线。
- F1-08／F1-09 → F1-12 → F1-D1：**开展试题重复性比对**。实际执行时点待确认，可在命审过程中重复执行。
- F1-D1 → F1-13：**完全重复**；该题退出或其他处置后的任务处理方式待确认，不直接推定整个计划失败。
- F1-D1 → F1-14 → F1-12：**高度重复，调整后重新比对**。
- F1-D1 → F1-15：**按确认规则可进入审核**，不把“非完全重复”自动等同于质量合格。
- F1-15 → F1-16 → F1-D2 → F1-17 → F1-D3 → F1-18 → F1-D4：各通过连线均写**本轮通过，进入下一轮**。
- 各审核判断 → F1-19：**需修改／退回**；F1-19 → F1-20 → 审核入口：**修改并重新提交，返审节点待确认**。
- F1-D4 → F1-20 → F1-21 → F1-22 → F1-E：**终审通过，完成版本与入库处理**。版本管理同时贯穿前序修改，不能只在终审后记录一次。
- F1-E → F1-23 → F1-07／F1-08 → 审核：**行业技术或政策变化，修订并重新审核**；是否另建计划待确认。
- F1-X使用独立虚线框连接“任务流程”，连线写**触发与返回节点待确认**，不能直接绘成绕过三审的通道。

1. 六个图名、泳道名、框内文字、条件连线和图旁资料均按本稿逐项放入图中；主图过密时拆成同编号子图，不删去支线。
2. 所有【待确认】内容保持虚线，不把提问变成既定流程。甲方确认后记录结论、确认人、日期及关联节点。
3. 流程中的每个人工操作对应角色表和操作权限；数据来源、任务受理范围、查看下载范围对应数据权限表。
4. 图间连接使用相同业务对象，不在F2、F3、F5各自重复生成互不关联的“最终试卷”，不在F3、F4分别维护互不一致的成绩。
5. 每项2.1—2.4条款在覆盖对照表中有位置；平台、性能、安全、实施要求在相应技术或项目材料保留，不以六图代替全部验收资料。

7. 对甲方提出的新处理节点、新终端、新统计指标或新角色，先识别是已有要求的细化还是新增范围，再确定是否纳入开发基线。
