# Demo人员职责改版记录

日期：2026-09-21。依据《技术协议（招标文件）.docx》及《系统角色专题.md》，改进现有Demo的角色表达、任务交接及权限模拟，不增加协议外业务流程。

## 本次调整

- 原四种角色保留为内部兼容分类，界面改为21位合成人员切换；每人具有结构化职责、所属机构、理论／技能范围和启停状态。
- 开发组织、命题负责、命题、初审、复审、终审、入库、题库管理、组卷、考试管理、阅卷管理、阅卷、仲裁、现场评分、电子书管理和阅读分别表达。
- 菜单和路由按职责开放。工作台区分个人待办和业务管理进度，切换人员重新创建页面，清除上一位人员的弹窗及编辑状态。
- 新命题计划可配置负责人和各轮处理人。已有计划可调整任务分工，未完成的审核任务同步其人员配置；试题状态、开发范围和任务受理人共同决定是否能够审核。
- 专家授权页使用勾选职责和启停状态，保存即影响操作。权限与审计页展示实际生效的人员授权，不再展示硬编码四角色矩阵。
- 评分身份绑定当前人员及分配的评委席位，不能在弹窗中代替其他评委提交。仲裁核对指定人员，现场评分核对任务受理人。
- 考生答卷按本人过滤并校验写入，学习用户不自动获得考试权限。
- 删除现场评分强制签字；继续保留协议要求的考生交卷确认签字及阅卷签字模拟。
- 审核轨迹记录实际人员，业务日志包含人员及职责；保留历史记录和旧浏览器业务数据，补齐缺失的任务映射。
- 七条业务主线更新为44个步骤，显式呈现复审、终审、入库、第二位专家评阅及组卷职责交接。

## 范围说明

所有账号均为合成演示身份。前端权限、数据过滤和操作校验不等于生产服务端授权或试题保密能力。机构归属用于表达组织关系，不代表已实现完整HR组织管理或固定的集团多级审批。

入库由命题负责人兼任、各轮指定不同人员等均为可识别的演示配置，不将其写为协议强制岗位或回避规则。没有新增监考操作端、领导端、试测功能或成绩审批链。两个开发子系统的独立部署仍是正式架构要求，本次前端改版不构成部署验收。
